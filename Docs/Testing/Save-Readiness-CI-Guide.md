# Save Readiness CI Guide

## Scope

`CampaignProfileReadiness` is a diagnostics/readiness-only report for Save Architecture V2. It records the current campaign profile metadata state so CI can collect the markdown as evidence, but report findings do not block builds or releases.

Phase 17 selects artifact preservation Option A:

- Existing tests remain contract-only.
- Persistent CI artifacts are generated by the editor command.
- Report findings are diagnostics-only and non-blocking.

This guide does not add a repository CI workflow. GitHub Actions or another CI system must be added only after CI ownership, runner environment, and artifact preservation behavior are explicitly decided in a later phase.

## Recommended Contract Test Command

Use the existing filtered full lane:

```bash
./run_tests.sh full --filter CampaignProfileReadiness
```

Do not use broad unfiltered `./run_tests.sh full` for this readiness lane. Do not add a new `run_tests.sh` lane yet. Do not add a new GitHub Actions workflow yet.

Reason:

- No repo-defined CI workflow currently exists.
- External CI ownership is unknown.
- The broad unfiltered full lane has known baseline red and must not be used as this readiness gate.
- The filtered command runs readiness report contract and policy coverage without treating unrelated full-lane failures as readiness regressions.

## Recommended Persistent Artifact Generation

Generate persistent upload artifacts with the editor command after the filtered contract test command. The command writes the markdown and does not delete it before CI upload.

Example external CI command shape:

```bash
Unity -batchmode -quit -projectPath "$PWD" \
  -executeMethod Game.Feature.Stages.Editor.CampaignProfileReadinessReportCommand.WriteDefaultReportFromCommandLine \
  -saveReadinessRunId "$CI_RUN_ID" \
  -saveReadinessCommitSha "$CI_COMMIT_SHA"
```

The run-id/commit arguments produce:

```text
TestLogs/SaveReadiness/<run-id>/<commit-sha>/CampaignProfileReadiness.md
```

An explicit output directory is also allowed when it resolves under `TestLogs/SaveReadiness`:

```bash
Unity -batchmode -quit -projectPath "$PWD" \
  -executeMethod Game.Feature.Stages.Editor.CampaignProfileReadinessReportCommand.WriteDefaultReportFromCommandLine \
  -saveReadinessOutputDirectory "TestLogs/SaveReadiness/$CI_RUN_ID"
```

The default command output remains restricted to:

```text
TestLogs/SaveReadiness/CampaignProfileReadiness.md
```

The command may fail for generation exceptions, invalid output paths, or forbidden output paths. Valid diagnostics/readiness findings in the generated report must not make the command fail.

## Artifact Policy

Recommended artifact glob:

```text
TestLogs/SaveReadiness/**/CampaignProfileReadiness.md
```

Policy:

- The artifact is a CI upload target, not a source asset.
- The artifact must not be generated under `Assets/`.
- The artifact must not be generated under `Library/`, `ProjectSettings/`, or `Packages/`.
- The artifact must not be generated under `Application.persistentDataPath` or any save root.
- The artifact must not be generated at an arbitrary external path.
- The artifact file name is always `CampaignProfileReadiness.md`.
- The artifact must not be committed.
- `/TestLogs/SaveReadiness/` is ignored by Git.
- Contract tests may create and clean up temporary outputs.
- Persistent artifact upload must use the editor command output under `TestLogs/SaveReadiness/**/CampaignProfileReadiness.md`.

## Failure Policy

CI may fail for:

- Compile error.
- Test failure.
- Report writer contract violation.
- Invalid artifact path accepted by the writer.
- Forbidden wording.
- Forbidden runtime consumer.
- Report generation exception.
- Editor command generation exception.
- Invalid or forbidden editor command output path.

CI and release must not fail for valid diagnostics findings:

- Profile missing.
- Profile corrupt.
- Profile stale.
- `LastPlayedSlotNumber` mismatch.
- `importedSourceHash` mismatch.
- Reset tombstone present.
- Deleted guards present.
- Any valid diagnostics warning emitted by the readiness report.

## Non-Goals

This phase does not:

- Promote report warnings to release or build gates.
- Decide Steam Cloud upload/source file selection.
- Use the report as a Steam Cloud canonical source.
- Treat `profile.json` as production save truth.
- Wire the report into MainMenu, Gameplay, DemoStageControl, runtime UI, or production composition.
- Change `SaveSlotStore()` default PlayerPrefs behavior.
- Enable production `profile.json` writes.
- Integrate `CampaignSaveServiceFactory` or `CampaignSaveService` into production flow.
- Add `.github/workflows` files.
- Add a new `run_tests.sh` lane.
