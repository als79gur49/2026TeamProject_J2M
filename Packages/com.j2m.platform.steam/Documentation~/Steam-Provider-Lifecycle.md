# Steam Provider Lifecycle

This package contains the Steam lifecycle provider core only. It references
`Game.Platform.Runtime` and contains no Steamworks.NET reference or native payload.

The provider state machine owns pack-size/DLL observation, native initialization,
the single callback pump, shutdown-once, overlay observation, and bounded diagnostics.
A callback exception faults the provider and disables future callback pumps. Feature
methods are not added to `ISteamNativeApi`.

The separate `ISteamAchievementApi` is a Steam-specific transport capability used only
by the opt-in AppID 480 smoke coordinator. The runtime dependency bundle can point its
lifecycle and achievement interfaces at the same concrete adapter. The coordinator owns
no Steam initialization, callback pump, or native shutdown; its callback handles are
disposed before the overlay callback and native shutdown.

Installing the package does not change the Local default. The always-compiled Foundation
owns generic provider selection, and a compiled Steamworks.NET adapter only registers the
Steam factory. Foundation resolves that factory only when the process receives:

```text
-j2mPlatformProvider steam
```

If the adapter assembly is absent, the same explicit request remains visible to Foundation
and resolves as `RequestedProviderNotRegistered`; it never becomes a Local success. Unknown,
invalid, and conflicting requests also fail closed. With no provider argument, Local remains
the default even when the Steam factory is registered.

Achievement mutation requires an explicit Steam provider selection plus both
`-j2mSteamSmoke` and `-j2mSteamAchievementSmoke`. It is hard-gated to the provider-local
Spacewar policy (AppID 480 and `ACH_WIN_ONE_GAME`), exact runtime schema presence, valid
identity/login observations, and a locked before-state. Clear/reset operations are not
exposed. `steam_appid.txt` is not generated by either provider package.

The Steamworks.NET 1.65 `DllCheck.Test()` result is recorded only as an observation.
Its substantive check is disabled upstream, so it is not treated as an independent
compatibility PASS signal. `Packsize.Test()` remains the independent preflight.
